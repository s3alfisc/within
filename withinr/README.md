# withinr

R bindings for the [within](https://github.com/py-econometrics/within) Rust
fixed-effects solver, built with [extendr](https://extendr.rs/). The API
mirrors the Python package `within` — same objects, same arguments, same
defaults — with R conventions where they differ (1-based indices, `$` access,
data frames, factors, warnings).

## Build

Only handwritten sources are tracked: `R/*.R`, the Rust adapter in
`src/rust/{Cargo.toml,Cargo.lock,src/}`, `DESCRIPTION`, tests, and examples.
All glue — the extendr entrypoint, `.Call` wrappers, Makevars templates,
configure scripts, the Rust core snapshot, `NAMESPACE`, and `man/` — is
generated by one script. Run everything from the repository root.

Prerequisites: R >= 4.2 with build tools (Rtools on Windows), Rust/cargo >=
1.85 on `PATH` (in this repo, `pixi` provides one: `export
PATH="$PWD/.pixi/envs/default/bin:$PATH"`), and `tar` with xz support. Full
CRAN checks also need LaTeX and `checkbashisms`.

```sh
# One-time: the generation tools (development only, not runtime dependencies)
Rscript -e 'install.packages(c("rextendr", "roxygen2", "pkgload", "jsonlite", "processx"), repos = "https://cloud.r-project.org")'

# Generate all glue and docs, compiling the crate once (cargo downloads deps)
Rscript scripts/prepare-r-package.R

# Or: also vendor the locked crates into src/rust/vendor.tar.xz, so the
# source package installs offline (required for CRAN)
Rscript scripts/prepare-r-package.R --vendor

# Build, check, install
R CMD build --no-build-vignettes withinr
CARGO_NET_OFFLINE=true R CMD check --as-cran --no-manual withinr_0.1.0.tar.gz
R CMD INSTALL withinr_0.1.0.tar.gz

# Delete every generated file again (incl. the Cargo target directory)
Rscript scripts/prepare-r-package.R --clean
```

Other modes: `--no-document` writes the scaffolding and core snapshot without
compiling, which is enough for `cargo check`/`clippy` on the adapter (a fresh
checkout needs this before any `cargo` command, since the tracked
`Cargo.toml` points at the generated `document.rs` and `within-core/`).
`--check` fails if `within-core/` no longer matches `crates/`.

What `scripts/prepare-r-package.R` does:

1. Copies the workspace's `within` and `schwarz-precond` crates into
   `src/rust/within-core/` (runtime sources only), so the package builds
   without this repository or a crates.io release, including unreleased changes.
2. Runs `rextendr::use_extendr()` in a scratch package and copies its
   entrypoint, Makevars templates, configure/cleanup scripts, `tools/`, and the
   Rust `document` binary, adding `--locked` and a two-job cargo limit.
3. With `--vendor`, runs `rextendr::vendor_crates()`, strips precompiled
   WASI-only fixtures, writes `vendor.tar.xz`, and records crate authors and
   licenses in `inst/COPYRIGHTS`.
4. Runs roxygen, which compiles the crate; the `document` binary writes
   `R/extendr-wrappers.R` from the `#[extendr]` metadata, and roxygen writes
   `NAMESPACE` and `man/`.

After a Rust dependency change, update the adapter's lockfile before vendoring:

```sh
Rscript scripts/prepare-r-package.R --no-document
cargo check --manifest-path withinr/src/rust/Cargo.toml   # refreshes Cargo.lock minimally
Rscript scripts/prepare-r-package.R --vendor
```

Development loop, after generating once:

```sh
Rscript scripts/prepare-r-package.R --check   # is the core snapshot current?
Rscript -e 'pkgload::load_all("withinr"); source("withinr/tests/run_tests.R")'
cargo fmt --manifest-path withinr/src/rust/Cargo.toml -- --check
cargo clippy --locked --manifest-path withinr/src/rust/Cargo.toml -- -D warnings
```

Rerun `scripts/prepare-r-package.R` after changing an `#[extendr]` signature
or roxygen docs, or after editing the Rust core: the package compiles the
snapshot in `within-core/`, not `crates/`. `load_all()` builds in debug mode and
reuses `src/rust/target/debug`; `R CMD INSTALL` builds in release mode and the
generated Makevars deletes the target directory afterwards unless `DEBUG` is set.

## API

| Python (`within`)                                   | R (`withinr`)                                        |
|-----------------------------------------------------|------------------------------------------------------|
| `solve(design, y, weights, options, preconditioner)` | `within_solve(design, y, weights, options, preconditioner)` |
| `solve_batch(design, Y, ...)`                       | `within_solve_batch(design, Y, ...)`                 |
| `Effect(levels, intercept, slopes)`                 | `Effect(levels, intercept = TRUE, slopes = NULL)`    |
| `Design(design)`, `.n_obs`, `.n_dofs`               | `Design(design)`, `$n_obs`, `$n_dofs`                |
| `Solver(design, weights, preconditioner)`           | `Solver(design, weights, preconditioner)`            |
| `solver.solve(y, options)`, `.solve_batch(Y, options)` | `solver$solve(y, options)`, `$solve_batch(Y, options)` |
| `solver.preconditioner`, `.has_escalated`           | `solver$preconditioner`, `$has_escalated`            |
| `LsmrOptions(tol, maxiter, local_size)`             | `LsmrOptions(tol, maxiter, local_size)` or a plain `list(...)` |
| `PreconditionerConfig.Off()` / `.Diagonal()`        | `PreconditionerConfig$Off()` / `$Diagonal()`, or `"off"` / `"diagonal"` |
| `PreconditionerConfig.Additive(local_solver)`       | `PreconditionerConfig$Additive(local_solver)`, or `"additive"` |
| `PreconditionerConfig.Adaptive(local_solver, stall)` | `PreconditionerConfig$Adaptive(local_solver, stall)`, or `"adaptive"` |
| `config.Staleness(window, threshold)`               | `Staleness(window, threshold)`                       |
| `config.LocalSolverConfig(approx_chol, schur, dense_threshold, scaling)` | `LocalSolverConfig(...)`, same arguments |
| `config.ApproxCholConfig(seed, split_merge)`        | `ApproxCholConfig(seed, split_merge)`                |
| `config.ApproxSchurConfig(split)`                   | `ApproxSchurConfig(split)`                           |
| `config.Schur.approximate(cfg)` / `.exact()`        | `Schur$approximate(cfg)` / `Schur$exact()`           |
| `config.ScalingConfig(tolerance, max_iterations, on_failure)` | `ScalingConfig(...)`, `on_failure = "warn"` or `"error"` |
| `Preconditioner(bytes)`, pickling                   | `Preconditioner(raw)`, `p$serialize()`               |
| `p.apply(x)`, `.nrows`, `.ncols`, `.config`, `.build_duration_seconds` | `p$apply(x)`, `$nrows`, `$ncols`, `$config`, `$build_duration_seconds` |
| `result.layout.index(term, level, column)`, `.address(i)` | `result$layout$index(term, level, column)` (vectorized), `$address(i)` (data frame) |
| `result.unidentified` (list of records)             | `result$unidentified` (data frame `term`, `level`, `column`) |
| build warnings as `UserWarning`                     | warnings of class `within_build_warning`             |
| `ValueError` / `TypeError`                          | errors of class `within_input_error`                 |
| `RuntimeError`                                      | errors of class `within_runtime_error`               |

Like Python, every config is checked when constructed and holds its effective
values (`LocalSolverConfig()$approx_chol$split_merge` is `2`); equal configs are
`identical()`, and `Preconditioner$config` round-trips
(`identical(p$config, PreconditionerConfig$Additive())`). Constructors accept
what Python's accept (`LsmrOptions(maxiter = 0)` is fine; a negative `tol` fails
when used), except that counts must fit R integers (`.Machine$integer.max`),
seeds must be whole numbers up to 2^53, and labels at most
`.Machine$integer.max`. Both error classes inherit from `within_error`.

R conventions:

* **Designs** may be a matrix or data frame of factor labels (one column per
  factor; factor and character columns use their level codes), a single
  vector for a one-way design, a list of `Effect()` terms, or a `Design()`.
  Numeric labels are non-negative whole numbers, used as given; gaps are fine.
* **Indices** — term, column, and positions in `x` — are 1-based, in results
  and in error and warning messages. Levels are your labels. Columns of a term
  are the intercept (if any), then its slopes.
* **Results** are classed lists with `print`, `coef()` (= `x`), and
  `residuals()` (= `demeaned`) methods. Batch results keep `colnames(Y)`.
* **Handles** (`Design`, `Solver`, `Preconditioner`, layouts) are external
  pointers: they do not survive `saveRDS()`. Persist a preconditioner with
  `saveRDS(p$serialize(), file)` and restore it with
  `Preconditioner(readRDS(file))`; the bytes are tied to the native wire format.

```r
library(withinr)

set.seed(1)
n <- 1000
firm <- sample(50, n, TRUE); year <- sample(10, n, TRUE)
tenure <- rnorm(n); y <- 2 * tenure + rnorm(n)

# Two-way fixed effects
fit <- within_solve(cbind(firm, year), y)
fit$demeaned

# Absorb fixed effects from y and regressors at once
batch <- within_solve_batch(data.frame(firm, year), cbind(y = y, tenure = tenure))

# Varying slopes: firm intercepts plus firm-specific tenure slopes, and year FE
slopes <- list(Effect(firm, slopes = tenure), Effect(year))
fit <- within_solve(slopes, y)
fit$x[fit$layout$index(term = 1, level = 7, column = 2)]  # firm 7's slope

# Reuse: one design, one solver, a serializable preconditioner
solver <- Solver(Design(slopes), preconditioner = PreconditionerConfig$Additive(
  LocalSolverConfig(schur = Schur$exact())
))
solver$solve(y, LsmrOptions(tol = 1e-10))
p <- Preconditioner(solver$preconditioner$serialize())
within_solve(slopes, y, preconditioner = p)$converged
```

The default `PreconditionerConfig$Adaptive()` starts on the diagonal and builds
additive Schwarz only when the contraction stalls; a solver's `$preconditioner`
is the diagonal base carrying the ladder until then, and the Schwarz map after.
Reuse a built preconditioner only with the same design and weights.

Native computation uses a private pool of one thread (an adaptive build may add
a second), keeping default use within CRAN's two-core limit. Set
`Sys.setenv(WITHINR_NUM_THREADS = "8")` before the first solve to use more.
Only Rust computation runs on the workers; R allocations stay on the R thread.

The tests compare weighted and varying-slope residuals with base R least
squares, and cover every config object, batches, persistent handles,
serialization, gappy labels, unidentified directions, adaptive escalation, and
invalid inputs. `benchmarks/benchmark_fixest_demean.R` compares against
`fixest::demean()`.
